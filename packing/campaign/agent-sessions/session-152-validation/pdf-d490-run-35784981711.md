The first changed file byte is 568,134, inside object 220. That object is the content
stream for page object 204, the document’s page 21. Its compressed stream is 6,121 bytes
in the stored file and 6,125 bytes in the fresh draw.
After decompression, the streams differ in one text matrix:

```text
stored: /F11 16 Tf
        1 0 0 -1 70.34375 18483.219 Tm
        <00DC> Tj

fresh:  /F11 16 Tf
        1 0 0 -1 70.34375 18483 Tm
        <00DC> Tj
```

The `/F11` glyph is the first `≥` in the version-history sentence “T-025 proves s(11) ≥
191/50 = 3.82.” The next `≥` and the `=` on the same line do not move.
Poppler 25.05.0 extracts the same text from both PDFs and reports only this glyph’s
vertical bounds as changed, apart from the document dates:

```text

fresh:  xMin=142.756373 yMin=210.409916 xMax=152.092119 yMax=224.509532
```

## Disposition

The bytes establish a 0.164246-point vertical movement of one glyph.
They do not establish a DOM, font-loading, math-settlement, or Chromium cause.
The source receipt, all embedded font objects, the other page objects, and the rest of
page 21 agree. This is another occurrence of the single-glyph baseline instability
tracked by D-490 and `think-ptit`.

The exact stored-artifact comparison remains unchanged.
It correctly rejected the first candidate.
Two later hosted attempts passed without a source change; those attempts may have used
different runners, so they do not establish same-host intermittence, erase the failed
attempt, or prove its cause.
