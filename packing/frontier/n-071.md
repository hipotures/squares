# `s(71)` — open

**External intake, 2026-09-22.** wand125’s retained source reports
`s(70) >= 171/20 = 8.55`; monotonicity carries the reported bound to `n = 71`. The
complete exact replay verifies the n70 premise, so the same monotonicity argument
verifies the bound at `n = 71`.

Open. The best known packing gives `s(71) ≤ 8.94407156`, and the verified lower bound is
`8.55`, leaving a gap of about `0.3941`.

## The verified upper bound is a ceiling

`verified_upper_bound` for this case is `9`, which is **larger** than the best known
`8.94407155757031` two fields above it.
It is not a tighter reading of the same packing and it is not the value of `s(71)`: it
is the strongest ceiling this repository can certify from its own evidence — the trivial
grid bound `⌈√71⌉ = 9` — and it trails the reported construction by `0.05592844242969`.

Its `exact_form` is the exact form of that ceiling, never of `s(71)`. `s(71)` is not
known exactly; `status` stays `open`, and the `mathematics` blocker in the frontmatter
names the gap. Read `reported_upper_bound` for the best known side length.

Found by Thomas Schadt in 2025, via simulated annealing.

## The lower bound

The complete n70 exact replay verifies `171/20`; deleting one square from any
hypothetical packing proves the same lower bound for n71. A second interval
implementation or generalized native importer would add confirmation and reuse, but it
is not a missing premise of this monotone consequence.

Nagamochi’s earlier general closed form remains part of the evidence history and applies
to every `N ≥ 4`:

```
s(N) ≥ min{ ⌈√N⌉,  √(N − 2⌊√N⌋ + 1) + 1 }
```
