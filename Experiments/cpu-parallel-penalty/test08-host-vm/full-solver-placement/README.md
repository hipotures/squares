# Full-solver placement transfer check

This tests whether the large 8-worker native placement gain transfers to the
accepted n=12, side=99/25 production solver. It does not change production
source. Every solve is required to converge at 23 rounds, 5842 rows,
objective `12.217676366606236`.

Run from `packing/`, with the project environment and thread caps:

```sh
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=.
uv run --frozen python ../Experiments/cpu-post-integration-profile/scripts/baseline.py --workers 8 --samples 3 --target-seconds 20 --output-dir ../Experiments/cpu-parallel-penalty/test08-host-vm/native-placement-control/full-solver-unpinned-w8
uv run --frozen python ../Experiments/cpu-post-integration-profile/scripts/baseline.py --workers 16 --samples 3 --target-seconds 20 --output-dir ../Experiments/cpu-parallel-penalty/test08-host-vm/native-placement-control/full-solver-unpinned-w16
taskset -c 0-7 uv run --frozen python ../Experiments/cpu-post-integration-profile/scripts/baseline.py --workers 8 --samples 3 --target-seconds 20 --output-dir ../Experiments/cpu-parallel-penalty/test08-host-vm/full-solver-placement/full-solver-guest-affinity-only-w8
```

For the physical-plus-guest pinned case, as root on PVE run the one-time
`HOST_TASK.md` using the shared virtiofs directory. It saves and pins VM 207
vCPU thread `i` to physical CPU `i` and publishes `SOLVER8_PINNED`. Then on
the VM execute `run-pinned-solver.py`; it invokes the same baseline command
inside `taskset -c 0-7`, writes raw results to `full-solver-pinned-w8/`,
and publishes `SOLVER8_RESTORE` even if the benchmark fails. The host
wrapper restores exact original affinities and copies receipts to
`host-evidence/`. An independent 8-minute timer guards restoration.

All important samples lasted at least 18.8 seconds. The processed summary
and 66-solve trajectory audit are generated by
`../native-placement-control/summarize.py`.
